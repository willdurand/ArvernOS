Detailed Description

Physical memory handoff between the board's bootloader and the MMU.

A board learns the physical memory layout from its bootloader and normalizes it here, so that the architecture's frame allocator and paging code stay board-agnostic.

  • memory_get_regions() returns the bootloader's E820-style memory map, i.e. what the machine says is RAM and what it says is not.
  • memory_get_reserved_areas() returns the ranges the bootloader has populated on top of plain RAM (kernel image, boot payloads, boot information), which the E820 memory map does not account for.

◆ memory_map_kernel_sections()

void memory_map_kernel_sections ( memory_section_map_fn map)

Invokes map for every allocated section of the kernel image, so that paging can identity map each section with the right permissions.

The implementation must report page-granular ranges and sections must not overlap each other.
